# Stage 1.5 replication-surface matrix

Status: Step 1B inventory of the current project-owned replication and send surfaces on the inspected `dev` tree.

This matrix consumes the committed Step 1A audit in [Stage-1.5-PurrNet-Capability-Audit.md](Stage-1.5-PurrNet-Capability-Audit.md). It does not re-infer PurrNet behaviour, and it does not authorize production changes. Every later Stage 1.5 implementation issue must reference one or more surface IDs below and preserve the listed authoritative owner and recipient rule unless that issue explicitly changes the contract.

**Single invariant:** current project-owned authority, recipient class, bootstrap rule, serializer contract, and telemetry boundary remain explicit for every inventoried surface before Step 2/4/5/6/7/8 work is drafted.

## Authoritative recipient classes

### Embodied observer state

Normal actor/world state uses the actor's PurrNet observer set. Eligibility remains:

```text
valid compatible WorldID / MapID / InstanceID
    AND
chunk/scene broad-phase relevance
    AND
authoritative 80 m entry / 96 m exit range policy
```

This is owned by `ChunkVisibilityRule` and `ServerInterestManager`. Visibility remains separate from Stage 1.4 Full/Nearby/Dormant simulation activity.

### Owner-private state

Inventory, equipment, talents, cooldowns, corrections, and owner-replicated stat definitions remain targeted to the controlling player only. They are not actor-observer state and must not be broadened to observers by this matrix.

### Explicit targeted state

An RPC to one specifically authorised `PlayerID` is recorded separately when the target is not simply “this actor's owner”. Target selection does not make another actor visible.

### Logical non-spatial state

Group and Raid requirements may eventually need group-member state that outlives physical proximity and world locality. This is a future logical recipient class only. No group visibility, group registry, or remote-identity exception is implemented or inferred here.

## Preservation and evidence rules

- `ActorComponent.WorldPositionD` remains the sole mutable accepted-position authority. The accepted-position SyncVar is a presentation snapshot and may only receive a later wire-cadence decision if the Step 1A SyncVar constraint is preserved.
- The current 64 m spatial-index cell size, 80/96 m actor visibility hysteresis, chunk/context compatibility, and Full/Nearby/Dormant activity model are retained.
- A missing late-observer bootstrap is a potential gap or future requirement, not a confirmed bug, unless the current source and the Step 1A audit prove the defect.
- Current server emission, recipient fan-out, per-connection outbound message, and per-connection outbound payload metrics are not fabricated from client handler metrics. Existing unsupported PurrNet transport counters remain unavailable.
- `Stage 1.5 class` uses only: **A — Authority/control**, **B — Combat-critical state/events**, **C — Movement presentation**, **D — Rare actor state**, **E — Owner-private state**, **F — Cosmetic transient**, **G — Logical group/social**. Ingress/control rows that are not server-to-client replication are labelled `Ingress/control — not a server->client frequency class`.
